# 效率计算模块使用说明

效率计算组件的公共接口位于 `packages/riic-efficiency/src/index.ts`，计算核心是纯函数，不读取当前项目的 `public/assets`、浏览器状态、旧项目 CSV、旧项目脚本或控制中枢人工映射表。

## 调用方式

```ts
import {
  calculateEfficiency,
  createEfficiencyCatalog,
} from "@arknights/riic-efficiency";

const files = await loadOperatorSkillFiles();
const terms = await loadEfficiencyTerms();
const catalog = createEfficiencyCatalog(files, terms);
const result = calculateEfficiency(scheduleDocument, {
  catalog,
  ruleset,
});
```

无人机加速场景使用独立接口；它和效率计算共享同一个 `ruleset`：

```ts
import { calculateDroneAcceleration } from "@arknights/riic-efficiency";

const droneResult = calculateDroneAcceleration(
  scheduleDocument,
  catalog,
  { 无人机: 20 },
  { ruleset },
);
```

术语由组件数据目录中的 `terms.json` 单独提供，`createEfficiencyCatalog` 接收干员技能文件和共享术语目录。`ruleset` 使用组件数据目录中的版本化 `ruleset.json`。技能文件缺失时，使用该干员会在对应队列结果中给出数据缺失提示，但不会阻断其他设施的基础效率计算。

当前项目通过 `src/adapters/riicEfficiencyData.ts` 读取组件的 `data/operators`、`data/terms.json` 与 `data/ruleset.json`，并直接调用 `@arknights/riic-efficiency` 公共入口。宿主不再维护效率计算兼容层或第二份技能数据。

## 模拟器展示结果

排班模拟器在 Torappu 数据源下会自动加载效率目录并计算当前排班表：

- 设施内的每个队列小卡片只展示 `干员效率 / 设施最终效率`。干员效率使用 `operatorSkillEfficiency`，不包含心情提供的固定基础效率和带 `stack: "max"` 的直接设施效率；设施最终效率使用 `efficiency`。
- `zeroOpBonus` 只清除目标设施上其他干员的技能效率；跨设施技能也按最终目标设施处理。同类 `zeroOpBonus` 拥有者彼此豁免，`except` 标记的来源和设施级 `stack: "max"` 效率保留，干员心情效率不受影响。
- 技能互斥使用技能效果上的 `suppresses` 字段；在同一目标设施上，被列出的技能效率不参与计算，但其他未被列出的技能节点仍然生效。
- “计算结果”区域按产物分别汇总排班表的平均每日产出，避免不同队列选择不同产物时把数值显示在错误的产物名下；材料变化同时按每小时显示。
- “计算结果”区域按队列显示当前大于 0 的基地点数、直接产出来源和派生来源；`basePointConvert` 不减少来源点数，派生结果可以继续参与下一条点数规则。
- 通用设置的基地点数显示固定列出当前 17 个基地点数，默认全部显示；隐藏设置只影响结果展示，不影响计算值或导出数据。
- 会客室以线索为产物单位，基础产出为 1 条/20 小时，线索上限为 11 条；`ProductionValue.conversion` 记录基础周期和每条线索折算 40 信用点，页面同时展示信用点折算值。
- `ProductionValue.baseAmountPerHour` 和 `baseMaterialPerHour` 固定表示 100% 效率下的产出与材料流；`amountPerHour` 和 `materialPerHour` 表示当前效率，`effective*` 表示容量模拟截断后的有效值。材料流使用有符号数，消耗为负数。
- “计算步骤”区域只保留有产出、容量或技能明细的设施，按队列和设施展开，并列出生效技能明细和心情修正明细。
- 设施结果同时展示基础/实际/有效速率、材料、容量、订单摘要和爆仓状态；页面展示直接消费计算结果，不在模板中重新实现效率或产出公式。
- `FacilityCapacity.segments` 记录队列内的容量分段，`capacity.total`、`skill` 表示队列结束时的容量值；爆仓时间按这些分段检查容量变化。
- 非 Torappu 数据源暂不显示效率结果，因为独立技能 JSON 只保证与当前 Torappu 干员 ID 对应。
- 设施区域下方、计算结果框体上方的排班提示由 `buildEfficiencyNotices({ document, result, efficiencyError })` 生成。定时换班空档、无人机爆仓、自动休整未达预期和设施爆仓为 `Info`；布局电力不足、心情继承异常、工作后心情降至 0 和菲亚梅塔恢复异常为 `Warning`；数据读取失败、换班时间无效和缺失干员技能数据为 `Error`。生成函数不执行效率计算，也不读取宿主状态。
- 导入额外设施提示由 `buildImportedExtraRoomsNotice(document)` 生成可关闭的 `Error`；模拟器只在导入确认时调用，提示持续到关闭或切换排班表，不阻断已登记设施的计算。
- 爆仓风险明细显示为“队列名 · 设施 · 干员列表：将在工作 X 小时后爆仓”；达到容量时显示“将立即爆仓”。

`dailyHours` 表示排班循环总时长。每日产出按各队列的 `amountPerHour × durationHours` 加权后除以总循环时长，再换算为 24 小时产出；因此排班队列总时长不必固定为 24 小时。

## 结果展示数据

结果区的数据结构由 `buildResultDisplay(result, options)` 产出。返回的 JSON 里没有"如何显示"的字段：没有格式化指令、单位提示、样式标记、图标键或装饰标题；文本以模板加原始数值给出，显示交给函数。

```ts
import {
  buildResultDisplay,
  calculateSanityValues,
  DEFAULT_SANITY_SETTINGS,
  formatDisplayValue,
} from "@arknights/riic-efficiency";

const display = buildResultDisplay(result, {
  sanityValues: calculateSanityValues(DEFAULT_SANITY_SETTINGS),
  droneAcceleration,
  facilityLabel: (facility) => formatFacilityResultLabel(facility, layout),
  basePointLabel: (term) => formatBasePointLabel(term, terms),
  basePointSource: (source) => formatBasePointSource(source, terms),
  visibleBasePointTerms: new Set(visibleTerms),
  sourceFacilityForProduct: (product) =>
    resultPresentationSourceFacility(product, result),
});
```

### 一个值长什么样

```json
{
  "key": "production-base-rate",
  "label": { "template": "基础速率" },
  "value": { "template": "{0}/小时", "raws": [{ "value": 427.73 }] }
}
```

- `template` 是文本骨架，`{n}` 是第 n 个原始数值的位置。
- `raws[n].value` 是原始数值；`raws[n].signed` 为 `true` 表示这是有符号增量（显示时应带 `+`／`-`），其余情况按普通数值显示。
- 单位、百分号、括号、分隔符都在 `template` 里，不在 `raws` 上。

### 取值函数

| 函数                                     | 作用                                                                                                                         |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `formatDisplayValue(value, format?)`     | 模板 + 原始值 → 成品字符串；`format` 可传入自定义的 `(raw, index) => string`，例如宿主用它逐数字格式化以支持悬停显示原始精度 |
| `formatDisplayNumber(raw)`               | 单个原始值的默认格式化：`signed` 时加符号                                                                                    |
| `flattenResultDisplay(display, format?)` | 把整份数据摊平成 `{ level, key, label?, text }` 行数组，适合只要成品文本的调用方                                             |

```ts
for (const row of display.calculationSteps.facilitySteps.steps[0].sections[0]
  .rows) {
  console.log(formatDisplayValue(row.label), formatDisplayValue(row.value));
}

for (const line of flattenResultDisplay(display)) {
  console.log("  ".repeat(line.level), line.label ?? "", line.text);
}
```

### 返回值结构

- `display.dailyOutput`：`label`、`cycleHours`、`tiles`（`product` 是产物名，`main` 是主数值，`lines` 是净收入、未计入、理智等行）、`totalTile`、`empty`、`warning`。
- `display.droneStrategy`：无人机策略区的标题、输入框标签、占位符、说明、空状态和策略错误文案。
- `display.droneScenarios`：按产物分组的场景，每个场景带两组结果格子。
- `display.calculationSteps`：`maaDrone`、`dailyOutput`、`basePoints` 三个分区，加上 `facilitySteps`。分区里是 `cards`（每列一张），卡片里是 `sections` 与 `rows`；有 `entries` 的区块按其形状区分用途（`cells` 是横排候选行、`value` 是"标题 + 数值"的条目、只有 `title` 和 `rows` 是分组条目）。

`facilitySteps` 只保存一份"队列 × 设施"数据，两种排列按需拼接：

```ts
import {
  buildFacilityStepCards,
  buildFacilityStepPanes,
} from "@arknights/riic-efficiency";

const { plans, steps } = display.calculationSteps.facilitySteps;
const byQueueCards = buildFacilityStepCards({ plans, steps }); // 按队列排列
const byFacilityPanes = buildFacilityStepPanes({ plans, steps }); // 按设施排列，含缺列占位
```

### 由调用方决定的部分

包内不再提供这些字段，调用方按自己的规则决定：

| 原先的字段                                                   | 现在由谁决定                                                             |
| ------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 数值格式名（`number`／`production`／`efficiency`／`signed`） | `raws[].signed` 表达"有符号增量"，其余三种格式化结果完全相同，无需区分   |
| 单位提示                                                     | 模板里已有显示单位；悬停等场景可从占位符后紧跟的字面量取                 |
| 弱化（`muted`）                                              | 已移除，不再有弱化样式                                                   |
| 加粗与否（`emphasis`）                                       | 已移除，行值统一按调用方的默认样式渲染                                   |
| 区块布局种类（`kind`）                                       | 由区块结构推导（是否有 `entries`、`entries[].cells`、`entries[].value`） |
| 每日产出净量卡样式（`netOnly`）                              | `tile.main.raws[0].signed === true` 即"只有净量"                         |
| 图标键（`icon`）                                             | 格子带 `product`（产物名），调用方据此查图标                             |
| 装饰标题（`eyebrow`）                                        | 由调用方自己写                                                           |

`visibleBasePointTerms` 只影响基地点数是否出现。`facilityLabel`、`basePointLabel`、`basePointSource` 不传时退回组件内的默认拼接，术语名称会退化为术语键。

## 第一版边界

- `processing` 和 `training` 保留在排班数据中，但不生成产出或效率结果。
- 宿舍不自动分配休整干员；宿舍技能可以参与基地点数和未来扩展所需的中间数据计算。
- 当前实现容量速率级爆仓：`firstItemProgress` 可使用全局数字或按设施 ID/设施类型的 map，`overflowMode='zero'` 按爆仓时间截断计划内有效产出，`overflowMode='continue'` 保留计划产出。它不模拟完整库存过程。
- 孑精 0 和精 1 的单人最大技能效率均为 40%。精 1 保留精 0 的 `tradeGapEff`，同时按贸易站基础订单上限计算固定的 `tradeSpd`；精 1 单人额外订单上限为 0，组合时按其他干员效率扣减订单上限，额外订单净值允许为负，最终总上限才按基础值加技能值并将下限限制为 1，因此不会把精 0 的差值贡献重复算成 4%。精 0 的 `tradeGapEff` 在 `preferMaxJieEfficiency=true` 时保持最大效率，关闭时按 `firstItemProgress` 作为首单已完成进度，并按当前贸易订单摘要的期望耗时逐单积分。已有订单数量使用排班设置中的 `tradeOrderCount`，不使用百分比字段。固定订单或缺少订单分布时回退为最大效率。
- 发电站以全设施组计算无人机产出，多座发电站不直接倍增基础产出速率。
- 贸易站特殊订单和订单上限联动在设施属性与产出层分别处理，不能把 `tradeOrder` 或 `orderLimit` 当作普通效率百分比相加。

## 排班设置默认值

未设置时，计算器使用：`clueExchanging=true`、`dormFullTreat=true`、`fiammettaMode='direct'`、`fiammettaDirectCount=3`、`preferMaxJieEfficiency=true`、`overflowMode='continue'`、`firstItemProgress=0`。模拟器在计算结果前提供计算设置弹窗，线索交流、宿舍满员计算和爆仓模拟使用开关，首件进度使用全局百分比输入。显示层只应格式化结果，不在核心计算中提前四舍五入。
