# 效率计算模块使用说明

效率计算模块的外部接口位于 `src/utils/efficiency/index.ts`，计算核心是纯函数，不读取旧项目 CSV、旧项目脚本或控制中枢人工映射表。

## 调用方式

```ts
import { calculateEfficiency, loadEfficiencyCatalog } from "@/utils/efficiency";

const catalog = await loadEfficiencyCatalog(baseData.operators, baseData.terms);
const result = calculateEfficiency(scheduleDocument, catalog);
```

`loadEfficiencyCatalog` 按当前 Torappu 干员 ID 读取 `public/assets/operator-skills/{id}.json`，并从当前项目的 `BaseData` 生成阵营和技能术语成员表。缺失或无法解析的技能文件会跳过，使用该干员时由 `calculateEfficiency` 在对应队列结果中给出警告；这不会阻断其他干员的基础效率计算。`calculateEfficiency` 只接收排班表和目录，返回每个队列、每座设施、每日平均产出、属性和心情轨迹。

## 模拟器展示结果

排班模拟器在 Torappu 数据源下会自动加载效率目录并计算当前排班表：

- 设施内的每个队列小卡片只展示 `干员效率 / 设施最终效率`。干员效率使用 `operatorSkillEfficiency`，不包含心情提供的固定基础效率和带 `stack: "max"` 的直接设施效率；设施最终效率使用 `efficiency`。
- `zeroOpBonus` 只清除目标设施上其他干员的技能效率；跨设施技能也按最终目标设施处理。同类 `zeroOpBonus` 拥有者彼此豁免，`except` 标记的来源和设施级 `stack: "max"` 效率保留，干员心情效率不受影响。
- “计算结果”区域按产物分别汇总排班表的平均每日产出，避免不同队列选择不同产物时把数值显示在错误的产物名下；材料变化同时按每小时显示。
- “计算结果”区域按队列显示当前大于 0 的基地点数、直接产出来源和派生来源；`basePointConvert` 不减少来源点数，派生结果可以继续参与下一条点数规则。
- 通用设置的基地点数显示固定列出当前 17 个基地点数，默认全部显示；隐藏设置只影响结果展示，不影响计算值或导出数据。
- 会客室以线索为产物单位，基础产出为 1 条/20 小时，线索上限为 11 条；`ProductionValue.conversion` 记录基础周期和每条线索折算 40 信用点，页面同时展示信用点折算值。
- “计算步骤”区域只保留有产出、容量、技能明细或干员贡献的设施，按队列和设施展开，显示 `baseEfficiency + operatorEfficiency + operatorSkillEfficiency + facilitySkillEfficiency = efficiency`，并列出逐干员组合贡献、生效技能明细和心情修正明细。
- 设施结果同时展示基础/实际/有效速率、材料、容量、订单摘要和爆仓状态；页面展示直接消费计算结果，不在模板中重新实现效率或产出公式。
- 非 Torappu 数据源暂不显示效率结果，因为独立技能 JSON 只保证与当前 Torappu 干员 ID 对应。

`dailyHours` 表示排班循环总时长。每日产出按各队列的 `amountPerHour × durationHours` 加权后除以总循环时长，再换算为 24 小时产出；因此排班队列总时长不必固定为 24 小时。

## 第一版边界

- `processing` 和 `training` 保留在排班数据中，但不生成产出或效率结果。
- 宿舍不自动分配休整干员；宿舍技能可以参与基地点数和未来扩展所需的中间数据计算。
- 当前实现容量速率级爆仓：`firstItemProgress` 可使用全局数字或按设施 ID/设施类型的 map，`overflowMode='zero'` 按爆仓时间截断计划内有效产出，`overflowMode='continue'` 保留计划产出。它不模拟完整库存过程。
- 精 0 孑订单逐单衰减和 `orderProgress` 动态订单状态尚未实现；这些字段仍保留在 `ScheduleSettings`，模拟器会明确提示该边界。
- 发电站以全设施组计算无人机产出，多座发电站不直接倍增基础产出速率。
- 贸易站特殊订单和订单上限联动在设施属性与产出层分别处理，不能把 `tradeOrder` 或 `orderLimit` 当作普通效率百分比相加。

## 排班设置默认值

未设置时，计算器使用：`clueExchanging=true`、`dormFullTreat=true`、`featherFixedOps=[]`、`preferMaxJieEfficiency=true`、`overflowMode='continue'`、`firstItemProgress=0`。模拟器在计算结果前提供计算设置弹窗，线索交流、宿舍满员计算和爆仓模拟使用开关，首件进度使用全局百分比输入。显示层只应格式化结果，不在核心计算中提前四舍五入。
